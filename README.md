# xkcd-searcher
### Проект написан в рамках практических курсов от копмании YADRO.
### Предствляет собой микросервисное приложение с гексагональной архитектурой для удобного поиска комиксов с сайта XKCD.
## Технологический стек

**Язык и базовые технологии:**
- **Go (Golang)** — основной язык разработки микросервисов.
- **net/http** — маршрутизация и обработка HTTP-запросов.

**API и Межсервисное взаимодействие:**
- **gRPC + Protocol Buffers (`protoc`)** — высокопроизводительное бинарное взаимодействие между внутренними микросервисами.
- **RESTful API** — публичный интерфейс (API Gateway) для взаимодействия с клиентами.
- **NATS (Core)** — брокер сообщений для асинхронного Event-Driven взаимодействия.

**Базы данных и Хранение:**
- **PostgreSQL** — основное реляционное хранилище данных.
- **pgx + sqlx** — высокопроизводительный драйвер и удобная обертка для работы с SQL.

**Алгоритмы и бизнес-логика:**
- **Snowball** — стемминг и нормализация текстовых запросов (NLP).

**Безопасность:**
- **JWT** — авторизация и защита эндпоинтов API.

**Конфигурация:**
- **cleanenv** — строгая типизация и парсинг конфигураций микросервисов из переменных окружения и `.env` файлов.

**Observability (Мониторинг и Логирование):**
- **VictoriaMetrics** — быстрая и легковесная Time-Series БД (Prometheus-совместимая) для хранения метрик.
- **Grafana** — визуализация метрик (кастомные дашборды для мониторинга RPS, Latency и шины NATS).
- **Loki** — централизованная агрегация и анализ логов со всех микросервисов.

**Тестирование:**
- **Unit & Integration Tests** — покрытие бизнес-логики и интеграций слоев.
- **testify** — удобные ассерты (assert/require) и моки.
- **gomock (uber-go/mock)** — автоматическая генерация моков для тестирования интерфейсов гексагональной архитектуры.

**Инфраструктура и CI/CD:**
- **GitHub Actions** — автоматизация процессов CI/CD (линтеры, тесты, сборка).
- **Docker & Docker Compose** — контейнеризация и локальный запуск всей инфраструктуры одной командой.

### Приложение состоит из 5 основных компонетнов.
1) **api** - rest шлюз, который принимает http запросы от пользователя и направляет соответсвующие gRpc запросы в другие сервисы, после собирает ответ и отправляет его пользователю.
- **Что было сделано**: Внедрил механизмы **Health Check** для мониторинга воркеров используя паттерн **Fan-out/Fan-in** и `sync.WaitGroup` для эффективной агрегации данных и **Graceful Shutdown** для корректного завершения работы. Реализовал маппинг gRPC-ошибок в соответствующие HTTP-статусы
2) **words** - сервис, который нормализирует фразу в срез нормализованных слов.
- **Что было сделано**: Реализовал стемминг на базе библиотеки **Snowball**, фильтрацию стоп-слов и валидацию входящих сообщений по размеру. Внедрил управление жизненным циклом запросов через `Context`.
3) **update** - сервис, который скачивает комиксы с xkcd и сохраняет из в бд.
- **Что было сделано**: Спроектировал и реализовал микросервис на Go для конкурентного сбора данных (**Worker Pool, Retry**). Интегрировал **PostgreSQL** с поддержкой миграций, реализовал gRPC-интерфейсы и обеспечил потокобезопасность логики через пакет `sync/atomic`.
4) **search** - сервис, который ищет по ключевым словам наиболее подходящие комиксы.
- **Что было сделано**: Разработал алгоритм ранжирования релевантности, основанный на коэффициенте Жаккара, для поиска наиболее подходящих комиксов по нормализованным текстовым запросам
5) **isearch** - улучшенный searсh, который строит индекс комиксов раз в заданное время, тем самым повышая производительность
- **Что было сделано**: Оптимизировал систему поиска, разработав и внедрив In-memory инвертированный индекс.

  Это позволило:
  
  Увеличить пропускную способность в 11.5 раз (с 2 000 до 23 000 RPS).
  Снизить задержку (latency) в 11 раз (с 62 мс до 5.5 мс).
  Повысить стабильность системы до 100% (SLA) под нагрузкой, полностью устранив ошибки деградации.
  Снять нагрузку с основной базы данных за счет периодического фонового обновления индекса по таймеру, используя паттерн инициатор
