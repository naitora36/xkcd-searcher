# xkcd-searcher
### Проект написан в рамках практических курсов от копмании YADRO.
### Предствляет собой микросервисное приложение с гексагональной архитектурой для удобного поиска комиксов с сайта XKCD.
## Технологический стек

**Язык и базовые технологии:**
- **Go (Golang)** — основной язык разработки микросервисов.
- **net/http** — маршрутизация и обработка HTTP-запросов.

**API и Межсервисное взаимодействие:**
- **gRPC + Protocol Buffers (`protoc`)** — высокопроизводительное бинарное взаимодействие между внутренними микросервисами.
- **RESTful API** — публичный интерфейс (API Gateway) для взаимодействия с клиентами.
- **NATS (Core)** — брокер сообщений для асинхронного Event-Driven взаимодействия.

**Базы данных и Хранение:**
- **PostgreSQL** — основное реляционное хранилище данных.
- **pgx + sqlx** — высокопроизводительный драйвер и удобная обертка для работы с SQL.

**Алгоритмы и бизнес-логика:**
- **Snowball** — стемминг и нормализация текстовых запросов (NLP).

**Безопасность:**
- **JWT** — авторизация и защита эндпоинтов API.

**Конфигурация:**
- **cleanenv** — строгая типизация и парсинг конфигураций микросервисов из переменных окружения и `.env` файлов.

**Observability (Мониторинг и Логирование):**
- **VictoriaMetrics** — быстрая и легковесная Time-Series БД (Prometheus-совместимая) для хранения метрик.
- **Grafana** — визуализация метрик (кастомные дашборды для мониторинга RPS, Latency и шины NATS).
- **Promtail**— агент сбора логов, отправляющий логи сервисов в Loki
- **Loki** — централизованная агрегация и анализ логов со всех микросервисов.

**Тестирование:**
- **Unit & Integration Tests** — покрытие бизнес-логики и интеграций слоев.
- **testify** — удобные ассерты (assert/require) и моки.
- **gomock (uber-go/mock)** — автоматическая генерация моков для тестирования интерфейсов гексагональной архитектуры.

**Инфраструктура и CI/CD:**
- **GitHub Actions** — автоматизация процессов CI/CD (линтеры, тесты, сборка).
- **Docker & Docker Compose** — контейнеризация и локальный запуск всей инфраструктуры одной командой.

### Приложение состоит из 5 основных компонетнов.
1) **api** - rest шлюз, который принимает http запросы от пользователя и направляет соответсвующие gRpc запросы в другие сервисы, после собирает ответ и отправляет его пользователю.
- **Что было сделано**: Внедрил механизмы **Health Check** для мониторинга воркеров используя паттерн **Fan-out/Fan-in** и `sync.WaitGroup` для эффективной агрегации данных и **Graceful Shutdown** для корректного завершения работы. Реализовал маппинг gRPC-ошибок в соответствующие HTTP-статусы. Обеспечил высокую отказоустойчивость и безопасность API Gateway, реализовав комплексную систему контроля трафика и авторизации. Внедрил механизмы **Concurrency Limiter** на базе конкурентного паттерна **семафор** и **Rate Limiter** на основе алгоритма **Token Bucket**, использовав паттерн **Заместитель (Proxy)** для защиты сервисов от деградации под экстремальной нагрузкой. Реализовал систему разграничения доступа на базе **JWT-токенов**, обеспечив надежную защиту критических операций от неавторизованных пользователей. Для мониторинга состояния системы в реальном времени настроил экспорт метрик в формате **VictoriaMetrics/Prometheus**, применив паттерн **Декоратор**, что позволило прозрачно собирать данные о задержках и HTTP-статусах запросов, не внося изменений в бизнес-логику приложения.
2) **words** - сервис, который нормализирует фразу в срез нормализованных слов.
- **Что было сделано**: Реализовал стемминг на базе библиотеки **Snowball**, фильтрацию стоп-слов и валидацию входящих сообщений по размеру. Внедрил управление жизненным циклом запросов через `Context`.
3) **update** - сервис, который скачивает комиксы с xkcd и сохраняет из в бд.
- **Что было сделано**: Спроектировал и реализовал микросервис на Go для конкурентного сбора данных (**Worker Pool, Retry**). Интегрировал **PostgreSQL** с поддержкой миграций, реализовал gRPC-интерфейсы и обеспечил потокобезопасность логики через пакет `sync/atomic`.
4) **search** - сервис, который ищет по ключевым словам наиболее подходящие комиксы.
- **Что было сделано**: Разработал алгоритм ранжирования релевантности, основанный на коэффициенте Жаккара, для поиска наиболее подходящих комиксов по нормализованным текстовым запросам
5) **isearch** - улучшенный searсh, который строит индекс комиксов раз в заданное время, тем самым повышая производительность
- **Что было сделано**: Оптимизировал поисковый сервис, полностью переработав архитектуру поиска.
Для устранения узкого места в виде постоянных обращений к БД спроектировал и внедрил in-memory инвертированный индекс с фоновым обновлением по таймеру (паттерн Initiator), что позволило вынести поисковую нагрузку из основной базы данных.
Для обеспечения актуальности данных перевел систему на событийно-ориентированную архитектуру, интегрировав брокер сообщений NATS для мгновенной инвалидации и перестроения индекса при изменении данных. Осознанно выбрал Core NATS без JetStream, так как в данном сценарии допустима потеря единичных сообщений, а отказ от персистентности позволил минимизировать latency и снизить архитектурную сложность.
Для наблюдаемости и контроля качества доставки разработал кастомный Grafana-dashboard, позволяющий отслеживать:
  
  - время перестроения индекса;
  - задержки обработки событий;
  - потенциальные потери сообщений;
  - общее состояние поискового контура под нагрузкой.ий в шине

Также я написал **ci/cd pipeline** используя **github actions**, централирзировал сбор логов используя **promtail** и **loki**, покрыл основную бизнес логику, а также ряд активных адаптеров **unit** тестами. Для изоляции компонентов и тестирования зависимостей внедрил автоматическую генерацию моков через **uber-go/mock** 
# Запуск

Проект использует **Makefile** для автоматизации рутинных задач.

Скрипты автоматически определяют доступную среду выполнения (**Docker** или **Podman**).

## Подготовка окружения

Перед началом работы установите инструменты генерации кода и линтеры:

```bash
make tools
```

---

## Запуск приложения

```bash
make up
```

После запуска сервис будет доступен по адресу:

```text
http://localhost:28080
```

---

## Тестирование

### Интеграционные тесты

```bash
make test
```

### Unit-тесты и проверка покрытия

```bash
make unit
```

# API Quick Start

## Health Check

Проверка доступности gateway и зависимых сервисов:

```bash
curl http://localhost:28080/api/ping
```

---

## Metrics

Получение Prometheus-совместимых метрик:

```bash
curl http://localhost:28080/metrics
```

---

## Авторизация

Получение JWT токена:

```bash
curl -X POST http://localhost:28080/api/login \
  -H "Content-Type: application/json" \
  -d '{
    "login": "admin",
    "password": "secret"
  }'
```

Сохранение токена:

```bash
TOKEN="your_jwt_token"
```

---

## Работа с данными

### Получить список слов

```bash
curl http://localhost:28080/api/words
```

### Запустить обновление БД

> Требуется авторизация

```bash
curl -X POST http://localhost:28080/api/db/update \
  -H "Authorization: Bearer $TOKEN"
```

### Получить статистику обновления

```bash
curl http://localhost:28080/api/db/stats
```

### Проверить статус обновления

```bash
curl http://localhost:28080/api/db/status
```

### Очистить БД

```bash
curl -X DELETE http://localhost:28080/api/db \
  -H "Authorization: Bearer $TOKEN"
```

---

## Поиск

### Стандартный поиск

```bash
curl "http://localhost:28080/api/search?q=golang"
```

Пример:

```bash
curl "http://localhost:28080/api/search?q=machine+learning"
```

---

### Indexed Search

Поиск через **in-memory inverted index**:

```bash
curl "http://localhost:28080/api/isearch?q=distributed+systems"
```
